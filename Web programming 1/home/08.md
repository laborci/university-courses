# 8. otthoni gyakorlat – Paraméterek, validáció és JSON-válasz

## Tanulási célok

Lekérdezési paramétereket olvasol ki egy URL-ből, ellenőrzöd a felhasználói bemenetet, és sikeres vagy hibás JSON-választ küldesz.

## Alapfogalmak

A `GET /add?a=2&b=3` URL-ben a `?` utáni rész a **lekérdezési karakterlánc**. Az `a` és `b` kulcsokhoz tartozó értékek **query paraméterek**. Ezek szövegként érkeznek meg, ezért nem szabad automatikusan számként kezelni őket.

A **validáció** azt ellenőrzi, hogy a kapott bemenet megfelel-e a program elvárásainak. Hibás bemenet esetén itt a `400 Bad Request` státuszkód a megfelelő válasz.

## Megoldás

Egészítsd ki a 7. gyakorlat `server.js` fájlját ezzel az útvonallal, még a 404-es válasz előtt:

```js
if (request.method === 'GET' && url.pathname === '/add') {
  const aText = url.searchParams.get('a');
  const bText = url.searchParams.get('b');
  const a = Number(aText);
  const b = Number(bText);

  if (aText === null || bText === null || !Number.isFinite(a) || !Number.isFinite(b)) {
    response.writeHead(400, { 'Content-Type': 'application/json; charset=utf-8' });
    response.end(JSON.stringify({
      error: 'Az a és b paraméter megadása kötelező, és mindkettőnek számnak kell lennie.'
    }));
    return;
  }

  response.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  response.end(JSON.stringify({ a, b, sum: a + b }));
  return;
}
```

Teszteld mindkét esetet:

- sikeres: `http://localhost:3000/add?a=2&b=3`
- hibás: `http://localhost:3000/add?a=alma&b=3`

Készíts képernyőképet mindkét válaszról. A hibaüzenet legyen a felhasználó számára érthető, de ne fedjen fel belső részleteket, például teljes szerverhibát vagy fájlútvonalat.
